# It Was You! — Chicken Party game plan

**Home tile:** Write something funny. Guess which friend wrote it. Get the room on your side.

It Was You! is a party game for **four or more players**, with **35 as a load-test target**. Up to six people write each round, and everyone eligible guesses. Put one answer on the TV, read it aloud, and give the room 30 seconds to make its case. Phones handle writing and voting. The full game also works on phones alone.

## Technical deep dive and reuse decisions

| Area | What exists and how to reuse it |
|---|---|
| Rooms and rematch | All three games use shared room codes, anonymous Firebase identity, the `joinGame` callable, and game/player subscriptions. Reuse [room-code helpers](../functions/src/shared/roomCodes.ts) and the [shared client service](../src/shared/gameService.ts). Preserve the existing UID on rejoin and the `rematchCode` redirect contract. The current join writes membership and the player document separately. Add an It Was You! branch to make admission and player creation atomic. Rooms use the same uncapped admission policy as the existing games. |
| Connectivity | [Presence](../src/lib/presence.ts) uses Realtime Database and the [shared trigger](../functions/src/index.ts) transfers hosting on disconnect and returns it to the original host on reconnect. Use the existing transport and handoff. Register only after confirming membership, and keep a disposable presence subscription that stops updating the old room on exit or rematch. The current helper does not retain its unsubscribe callback. Follow [Fowl Words' resume pattern](../src/games/fowl-words/hooks/useGame.ts), also refreshing the current round and own private view after backgrounding or reconnect. |
| Shared View | [The display service](../functions/src/shared/sharedView.ts) authorizes TV viewers and projects a separate sanitized feed for Flock Together and Fowl Words. Extend the existing display types and projector, `/shared/:code`, [Shared View shell](../src/shared/display/SharedView.tsx), `SharedViewLink`, standings, fullscreen, and reconnect feedback. Add one board for this game's phases. Use the same room and answer identifiers when subscribing and rendering so data from the previous answer can never flash on the TV. |
| Voting at party scale | Fowl Words' word selection has useful tap-to-vote UI, but its legacy `wordVotes` map contains player IDs. Adapt [Fowl Words live reactions](../functions/src/games/fowl-words/liveReactions.ts) instead for storage: an own-readable ballot and sharded count deltas that carry no voter identities. Its [scoring engine](../functions/src/games/fowl-words/scoringEngine.ts) also provides a precedent for private player views and folding ballots during authoritative scoring. Keep the new game's tally and scoring in its own module. |
| Timers and reveals | Use Truth or Turd's server deadline and host-confirmation patterns. Its UI relies on the host to request expiry. Use Fowl Words' joined-player expiry pattern so another phone can move the room forward if the host drops. Reuse the [presentation clock](../src/shared/presentationClock.ts) for synchronized countdowns and the brief reveal beat. |
| Style and art | Follow existing home tiles, lobbies, headers, scoreboards, Material 3 tokens, and the shared `BottomActionDock`. Reuse the existing transparent [comic hens](../public/images/generated-comic/midnight/): magnifying for the tile and guessing, thinking while waiting, excited at the reveal, and `hen-winner-v2` at the finish. Use the app's animation and reduced-motion styles. |

### Shared refactor scope

- Reuse the components and services already in `src/shared` for room subscriptions, eligibility, action placement, and Shared View. Extend the Shared View renderer with one game board.
- Extract one shared hook for game/player subscriptions and foreground refresh. Adopt it in all four games through their typed wrappers. Preserve the existing game return shapes and refresh behavior for each current game. It Was You! also refreshes its current round and own ballot. Keep the round subscriptions game-specific because Fowl Words combines the public round, private view, ballot, and reaction counts.
- Make the existing presence subscription disposable. Wire cleanup into the game pages so leaving or rematching removes the old connection listener and cancels its disconnect handler. Preserve the existing host transfer and reclaim rules. Verify that reconnecting after a rematch updates only the active room.
- Keep lobby, header, and scoreboard compositions local to each game. Revisit shared pieces once the new game is playable and the common UI and behavior are clear. Keep rules, scoring, and phase transitions in the game modules.

**First implementation milestone:** In the emulator, create and join a room through the existing flows, open Shared View, show one sample anonymous answer, change a vote, and reconnect. The phone must recover its own vote, the TV must recover the phase and tally, and neither may read another player's ballot or the unrevealed author. Verify this slice before building out the full game and prompt bank.

## Gameplay

1. **Preview the prompt.** The host can open writing or swap the prompt. Ship at least 60 original, family-friendly prompts, such as “What would be a terrible thing to hear from your GPS?” Draw without replacement within a session, including skipped prompts. If the deck runs out, the host can finish.
2. **Write something funny.** Up to six writers get **60 seconds** to submit one answer of up to 140 characters. Reject blank answers and exact duplicates after trimming and ignoring case. Everyone else sees the prompt and submission count. Start guessing when everyone submits, when the deadline arrives with at least three answers, or when the host confirms **Start guessing** with at least three. With fewer than three at the deadline, show a short message and offer a new prompt or the option to finish.
3. **Read it aloud and make your case.** Shuffle the submitted answers and show one at a time. Players get **30 seconds** to vote and change their pick. Keep candidate buttons in a fixed order. Show live bars, total votes cast, and the eligible voter count without showing voter identities. Voting closes at the deadline or when the host confirms **Reveal now** after at least one vote. The clock keeps running if everyone votes early.
4. **Reveal who wrote it.** Freeze the tally, highlight the room's guess or show the tie, then reveal the author after a brief beat. Phones show the player's points. The host advances when the room is ready. Remove revealed authors from the candidate list. When one author remains, the next advance reveals that answer automatically for zero points.
5. **See the standings.** Show round gains and cumulative standings after the final answer. The host can start a new round or finish. Tied players share their rank. Rematch carries over the room roster and resets scores, writer rotation, and prompt history.

**Scoring:** Get **1 point** if you guess right, plus **1 more** if the correct author is the sole leader. A tie, an incorrect room guess, or no room guess yields no room bonus. Authors may vote on their own answers and influence the tally, and earn zero for that answer. If Maya wrote the answer and wins 5–3, other players who picked Maya get two points each. If she loses 3–5 or ties 4–4, they get one point each.

## Implementation

- Add `it-was-you` as a peer game type and `/it-was-you/:code` as its route. Use `itWasYou`-prefixed callables and the [new-game playbook](new-game-playbook.md). Use one room-code flow and one Shared View route. Finish, abandon, and rematch use the existing status and redirect conventions.
- Require four connected players to open writing. Snapshot the connected voter roster at that point using the shared eligibility helpers. Pick up to six writers with the fewest previous writing opportunities, randomly breaking ties. Count an opportunity when writing opens. Keep eligibility fixed through the round. Late arrivals can watch and play next round. A disconnect leaves valid submissions and votes intact.
- Store the submitted text and author, shuffled answer order, and unrevealed author mappings in server-only round state. Put the player's own submission status and ballot in their private round view. Use game-specific Firestore guards for direct writes to game state, scores, and legacy answer paths. Only authenticated room members should be allowed to act.
- Each vote identifies its round, answer, and candidate. Within a transaction, validate eligibility, current phase, and server deadline, then update that player's ballot and a public count shard together. An unchanged ballot has no effect on counts. Initialize a fresh aggregate feed per answer and reuse the shared aggregate-listener pattern on phone and TV.
- At close, read committed ballots for the current answer and update the frozen tally, revealed author, cumulative scores, and round gains in one idempotent transaction. All actions that move the game forward carry the expected round and phase or answer. Use the server clock to reject late actions, and let connected joined phones request expiry with retries. If all phones leave, resume the expired phase on the first player's return.
- Keep host controls to start, swap prompt, start guessing early, reveal early, advance, end, and rematch. Show round number without a fixed total. Keep full standings between rounds so attention stays on the answer during debate.

## Verification and playtest

- **Score and lifecycle:** Check correct and incorrect room guesses, ties, no votes, author self-votes, and the last automatic reveal. Cover duplicate answers, early close racing expiry, votes on a stale answer, late arrivals, reconnection, and repeat requests.
- **Privacy and permissions:** Verify that another player, a TV viewer, and a signed-in nonmember cannot read ballots or hidden authors. Check that client writes cannot alter scores or advance phases. Verify that no future anonymous answer appears in any readable view.
- **Phones and TV:** Play one four-player phone-only round and one six-player round with the TV. Background a phone mid-phase, disconnect the host during voting, restore a saved vote, and follow a rematch on both phone and TV. Check readability from across the room and avoid flashing stale content during reconnect.
- **35 players:** Extend the existing [bot harness](bot-swarm-test-harness.md) with scripted answers and votes so this scenario needs no Gemini key. Exercise a 35-player join burst and successful admission above 35, changes near the deadline, real-time counts, and writer rotation. Compare frozen counts and score deltas with committed votes. Run the frontend build, Functions build and tests, and both existing Shared View regressions.
- **Live playtest:** Explain the rules once. Watch for answers being read aloud, players making a case, and votes changing after someone speaks up. If the clock frequently cuts off good debate, adjust the fixed window before adding settings.
